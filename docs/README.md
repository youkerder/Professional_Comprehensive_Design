## 2. `extracted_text/` —— 文本抽取

把 `.docx` / `.pptx` 转成纯文本，方便用编辑器全文搜索（原件的正文在 Word 里不好搜）。

| 文件 | 来源 |
|---|---|
| `timu.txt` | `实验题目-4.docx` |
| `目标检测实验指导书.txt` | `目标检测实验指导书.docx` |
| `目标跟踪实验指导书.txt` | `目标跟踪实验指导书.docx` |
| `使用OpenCV进行目标跟踪.txt` | `使用OpenCV进行目标跟踪.docx` |
| `pptx_all.txt` | 两个 `.pptx` 课件的文字汇总 |

重新抽取（DOCX）：

```bash
python tools/dump_docx.py docs/course_materials/目标检测实验指导书.docx > docs/extracted_text/目标检测实验指导书.txt
```

## 3. 技术报告结构

4 份报告统一放在 [`reports/`](../reports/)，命名：

```
reports/
├─ 01-object-detection.md
├─ 02-multi-object-tracking.md
├─ 03-video-summarization.md
├─ 04-video-retrieval.md
├─ figures/           # 报告插图：曲线、对比图、样例结果
└─ tables/            # 报告表格：指标 CSV / Markdown
```

每份报告包含以下章节：

1. **目标** —— 任务定义与验收标准
2. **实验环境** —— 硬件（CPU/GPU/显存）、系统、Python 与关键库版本。可直接引用 `envs/` 下的环境文件
3. **原理** —— 所用模型/算法的简要原理，不整段照搬上游资料
4. **数据集** —— 来源、规模、划分方式、预处理。给出统计表格
5. **实验步骤** —— 关键步骤 + 命令 + 关键参数（超参表）。命令要能直接复制运行
6. **实验结果** —— 数值指标表 + 可视化图（检测框、跟踪轨迹、摘要关键帧、检索结果）
7. **结果分析** —— 对比不同算法/不同超参的差异，解释原因，分析失败案例
8. **实验结论与心得** —— 遇到的问题、解决办法、可改进方向

### 图表编号约定
正文中的图表统一编号并在 `figures/` / `tables/` 中留同名文件，便于复用：

- 图：`图 1-1 训练损失曲线` → `reports/figures/01_loss_curve.png`
- 表：`表 1-1 不同学习率对比` → `reports/tables/01_lr_compare.csv`
